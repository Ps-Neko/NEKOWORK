## Affected Pages/Routes
이 plan은 web 서비스가 아닌 CLI 마이그레이션이므로 "page" 대신 **CLI 명령어 surface**로 매핑합니다.

- `nekowork check <pr-diff>` — wedge CLI 진입점. SHIP_READY/NO_SHIP verdict 출력. 30초 이내 완료 약속.
- `nekowork check --profile forge <pr-diff>` — forge mode 진입. forge-engine의 14-stage 활성화.
- `npm install -g @ps-neko/nekowork@alpha` 후 `nekowork --version` — fresh install verification.
- NEKOFORGE 레포 `https://github.com/Ps-Neko/NEKOFORGE` 접근 시 archive notice + redirect link 가시성.

## Key Interactions to Verify

- **Fresh install + first verdict (E2E)**: 깨끗한 macOS/Linux/Windows 머신에서 `npx -y @ps-neko/nekowork@alpha check fixtures/sample-pr.diff` 실행 → verdict 30초 이내 + REPORT.md / decision.json / quality-score.json 3개 산출물 생성.
- **Workspace dep resolution**: `packages/forge-engine/`에서 `import { Verdict } from '@ps-neko/quality-core'` 가 빌드 + 런타임 성공 (workspace:* protocol).
- **--profile forge routing**: `nekowork check --profile forge` 가 forge-engine의 14-stage worker factory를 호출. 기본 `nekowork check` 는 quality-core + nekowork-cli만 사용 (forge-engine import 안 함).
- **manifest builders**: `pnpm --filter nekowork-cli run build:claude` 등 4개 명령이 monorepo merge 후에도 NEKOWORK 기존 동작 그대로 (Claude/Codex/Cursor/Gemini 매니페스트 생성).
- **git history follow**: monorepo merge 후 `git log --follow packages/forge-engine/src/core/gate/index.ts` 가 NEKOFORGE 0.5.0-alpha 시절 커밋까지 추적 가능.

## Edge Cases

- **30초 budget overflow**: large diff (>500 lines)로 fixture 늘려 perf budget 초과 시 CI fail 정확히 잡히는지 (False Positive 0).
- **Workspace 외부 import 시도**: nekowork-cli에서 `import { internal } from '@ps-neko/forge-engine/internal'` 시도 시 forge-engine의 public API export만 노출되어 차단되는지 (tsconfig paths + `"exports"` 필드).
- **--profile forge 없이 forge 기능 호출**: `nekowork check`가 forge-only artifact를 요구하면 명시적 에러 ("requires --profile forge") 출력. silent fallback 금지.
- **Concurrent CLI**: 2개 nekowork check 동시 실행 시 임시 디렉토리 충돌 없음 (PID 또는 UUID 기반 isolation).
- **stdin diff input**: `cat pr.diff | nekowork check -` 형태 stdin 모드 (CI 사용 시).
- **NEKOFORGE 0.5.0-alpha → 0.2.0-alpha 다운그레이드 혼동**: 기존 NEKOFORGE 사용자(추정 0명이나 안전망)가 `npm install nekoforge` 시 deprecate 메시지 + 마이그레이션 가이드 표시.

## Critical Paths

### Path 1: First-time user wedge experience (E2E)
1. 깨끗한 디렉토리에서 `npx -y @ps-neko/nekowork@alpha`
2. CLI가 도움말 또는 첫 verdict 안내 출력
3. `npx @ps-neko/nekowork check fixtures/sample-pr.diff`
4. 30초 이내 verdict + 3개 산출물 생성
5. README headline 약속과 정확히 일치

### Path 2: 30-second regression fixture (CI gate)
1. `fixtures/perf/sample-pr.diff` 생성: 50라인 TS 파일 1개 변경 PR
2. CI step: `time pnpm --filter nekowork-cli run check fixtures/perf/sample-pr.diff`
3. wall-clock < 25s assertion (buffer 5s for runner variability)
4. failure 시 CI red + PR block

### Path 3: Workspace integrity (verify pipeline)
1. `pnpm install` 루트에서
2. `pnpm -r run verify` (typecheck + lint + depcheck + test 모든 패키지)
3. 모든 패키지 green
4. cross-package import 모두 resolve

### Path 4: --profile forge routing
1. `nekowork check fixtures/sample-pr.diff` → quality-core + nekowork-cli만 호출, forge-engine bundle 미포함 verify
2. `nekowork check --profile forge fixtures/sample-pr.diff` → forge-engine 14-stage worker factory 활성화, REPORT.md에 stage breakdown 포함
3. 두 경로 모두 verdict 생성 (SHIP_READY/NO_SHIP)

### Path 5: Existing forge-engine test suite preservation
1. NEKOFORGE의 tests/unit/{artifact,doctor,gate,hooks,integrations,rule-packs,rules,schemas,skill-packs,utils,workers} 모두 monorepo 이전 후 그대로 통과
2. `pnpm --filter forge-engine test` 실행 시 NEKOFORGE 0.5.0-alpha 때와 동일한 test count + green
3. recall 1.000, FP 0.000 benchmark 결과 유지

### Path 6: Git history audit (post-merge)
1. `git log --follow packages/forge-engine/src/core/gate/index.ts` → NEKOFORGE 시절 커밋 보임
2. `git log --follow packages/nekowork-cli/scripts/build-claude.js` (또는 .ts 이식 후 동일 위치) → NEKOWORK 시절 커밋 보임
3. `git log --oneline | grep -c 'verified-harness'` ≥ 1 (NEKOFORGE 분리 전 커밋 보존 증명)

## Test Coverage Targets

- packages/quality-core: 100% (인터페이스 + schema 유효성 검사)
- packages/forge-engine: NEKOFORGE 기존 커버리지 유지 (≥80% per 베타 진입 조건)
- packages/nekowork-cli: 80% (wedge CLI + manifest builders + --profile flag routing)
- Integration tests: 모든 cross-package import 경로 1개 이상 smoke 테스트
- E2E: Path 1 + Path 2가 CI에 포함 (회귀 게이트)

## Test Framework

- Unit: `node --test` (NEKOWORK 기존) + `tsx` (TS) — `pnpm -r run test`로 통합
- Coverage: `c8` 또는 native node coverage (--experimental-test-coverage)
- E2E: `node --test tests/e2e/` 별도 디렉토리, CI에서만 실행 (slow)
- Regression fixture: 위 Path 2 — wall-clock 측정은 `time` 또는 `process.hrtime`

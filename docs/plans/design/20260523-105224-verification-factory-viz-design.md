## Problem Statement

NEKOWORK 의 12-station verification factory 는 머릿속 구조이고 외부 audience 에게는 텍스트 `REPORT.md` 로만 보임. AI 코드 검증 카테고리 (Cursor/Claude Code/Codex 의 자체 PR review) 와 비교했을 때 wedge 메시지 — "AI 가 AI 를 review (opinion-based)" vs "deterministic rule + evidence (NEKOWORK)" — 가 첨 1초에 드러나지 않음. 빌더 모드 정신으로 '제일 멋진 버전' 의 visualization 을 한국 OSS 메인테이너 · 국내 AI dev 커뮤니티에게 보이는 게 목적.

## What Makes This Cool

> "Claude said LGTM. NEKOWORK blocked this line because rule X had evidence Y."

interactive replay 에서 한 PR 이 12-station 을 거치는 과정을 timeline scrubber 로 보여주고, **Claude review 의견 vs NEKOWORK rule 결과를 동시 frame 에 표시**. 정적 dashboard 가 아닌 narrative replay. wedge 차별점이 시각적 conflict frame 으로 박힘. (Codex cold read 가 "12 stations exist 가 killer 가 아니라 LGTM 충돌이 killer" 라고 정확히 지적함.)

## Constraints

- audience: 한국 OSS 메인테이너 + 국내 AI dev 커뮤니티 (사용자의 trust network, share velocity 짧음)
- channels: README hero GIF + GitHub Pages hosted demo + 한국 Slack/Discord push (A+C 조합)
- comparison anchor: Cursor / Claude Code / Codex 의 자체 PR review (메인테이너의 첨 비교 대상)
- core principle (P5): VISION.md "LLM 의견은 verdict 가 아니다" 침해 0건
- 6주 시계: 5-user wedge test 와 병행
- tech: monorepo packages/nekowork-cli 의 docs/ 하위 작업, no backend, GitHub Pages 무료 호스팅

## Premises

P1 — 한국 OSS 메인테이너는 visualization 첨 1초로 NEKOWORK 의 wedge 이해 가능 (텍스트 README 보다 인지 속도 빠르다).

P2 — "AI reviewing AI (Cursor/Claude Code self-review)" vs "deterministic rule reviewing (NEKOWORK)" 차별점은 첨 frame 에 1줄로 표현 가능.

P3 — hosted demo + README GIF + sample fixture 의 ship 비용 = 1.5주 이내 (CC ~20h).

P4 (revised, Codex challenge 흡수) — Slack/Discord push 시 메인테이너의 정성 반응 측정 — 첫 24h 안에 (a) ≥1명 "어떻게 install / 내 레포에서 돌릴 수 있나?" (b) ≥1명 "Cursor/Claude review 와 차이 무엇?" 비교 질문, 또는 (c) ≥1명 share / fork / star 시 wedge concrete 시그널. 0건 시 visualization 방향 또는 메시지 자체 의심 데이터. 이전 P4 의 "30% 수치" 는 근거 없음 → 제거.

P5 — visualization UI 는 evidence chain · `decision.json` 이 1차 시각화 대상, AI 출력은 `advisor-only` 라벨로 분리. UI 감사 체크리스트 별도 (Reviewer Concerns 참고).

## Cross-Model Perspective (Codex cold read, 2026-05-23, gpt-5.5)

5개 항목에서 critical 통찰을 받음. 본 doc 의 Recommended Approach + Open Questions + Success Criteria 에 5개 모두 흡수.

1. **더 굙은 컴셉 제안 — "Evidence Replay URL"**: "12 stations exist" 가 killer 가 아니라 "Claude said LGTM, NEKOWORK blocked rule X with evidence Y" 가 killer. → Approach B 의 핵 narrative 로 채택.

2. **가장 흥분점 인용**: 사용자가 Q5 에서 답한 "show our own repo's last 3 months of rule hits, trends, perf regressions, rule learning" 한 줄을 인용하며 "verification memory that compounds" 패턴으로 정의. → Future Expansion 의 north star.

3. **가장 약한 전제 — P4 (30% 수치)**: "Korean OSS maintainers will ask 'Can I run this on my repo in 3 minutes?' before they share." → P4 정성 관찰로 재집함.

4. **Weekend build 권고**: `packages/nekowork-cli/docs/demo/sample-pr.json`, `decision.json`, `REPORT.md`, `evidence/*.json`, `docs/visualizer/` GitHub Pages app, README hero GIF, first-frame wedge line `"LLM reviews give opinions. NEKOWORK ships evidence."` → Next Steps 의 파일 경로 와 정확 일치.

5. **Cross-cultural 우려**: Korean OSS 는 pragmatic + AI workflow tool 회의적. 첫 artifact 는 blunt + technical. 최악 objection: **"멋있긴 한데 CI 랑 뭐 다름?"** → Success Criteria 의 정성 응답 templates 준비 task 로 등록.

## Approaches Considered

### Approach A: Static Visualizer + 1 fixture (minimal)

Summary: 1주 ship, static SVG/HTML, GitHub Pages.
Effort: S (CC ~8h / human 3일), Risk: Low, Coverage: 6/10.

Pros:
- 가장 빠른 ship, GitHub Pages 호스팅 무료, P3 충족 여유 있음
- 어떤 부족함 조심으로도 ship 검증되는 첨 deliverable

Cons:
- Codex 권고 'Claude LGTM · NEKOWORK blocked' 핵심 narrative 내림 — frame 한계
- 1 fixture 라 heatmap · trend 없음 (Q5 north star 반영 적음)

Reuses: 기존 NEKOWORK README + alpha.11 의 `verify-pr` 실 산출물 (REPORT.md / decision.json)

### Approach B: Interactive Evidence Replay (chosen, Codex 권고)

Summary: 1.5주 ship, timeline scrubber + Claude review 가짜 vs NEKOWORK rule 비교, fixture 1개 → 3·5개 확장 경로 명시.
Effort: M (CC ~20h / human 1.5주), Risk: Med, Coverage: 10/10.

Pros:
- Codex cold read 두 핵 critique 모두 반영 (P4 재집 + Evidence Replay URL 핵바꿈)
- 'Claude said LGTM, NEKOWORK blocked rule X' 타임라인 frame 구현 → wedge 메시지 1초 이내 드러남
- fixture 1개로 시작 → 3·5개 → live data (Q5 north star) 확장 경로 명확
- share velocity 강함 (interactive demo URL 자체가 sharable artifact)

Cons:
- sample-pr.json + decision.json + evidence/*.json + Claude review 가짜 풀 셋 설계 (~5-8h)
- timeline scrubber UX 가 1주 멉이 아님 — 1.5주 추정 정확성 첨 사이클 후 재추정 (Reviewer Concern 등록)
- fixture writer 도구 별도 필요 (follow-up)

Reuses: alpha.11 의 `verify-pr` 실 산출물 schema, 기존 packages/nekowork-cli/docs/ 디렉토리

### Approach C: Live Self-Hosting Dashboard (creative, north star 100%)

Summary: 1개월 ship, Q5 north star 100% 구현, 자기 레포 시계열 trend dogfood.
Effort: L (CC ~40h / human 1개월), Risk: High, Coverage: 10/10.

Pros:
- Q5 의 "우리 레포의 지난 3개월" 100% 구현 — dogfood 극대
- station heatmap · trend · perf regression 모두 자연

Cons:
- 1.0 wedge (30초 npx CLI) 와 멀어짐 — "이게 널이다 아니라 우리 레포" 첫 반응 위험
- build complexity 고 — `.nekowork` 폴더 schema 표준화 + 시계열 storage + 시각화 인프라
- 6주 시계와 충돌 — ship 이 느려서 5-user wedge test 와 겹침

Reuses: `.nekowork/evidence/` 폴더 (이미 alpha.11 에 출력 중), GitHub Actions 의 verification 결과

## Recommended Approach

**Approach B: Interactive Evidence Replay.**

이유:
1. **Cross-model 합의**: Codex weekend build 권고 = Approach B 와 정확 일치 (1 fixture 시작 + interactive replay). Claude 의 추천도 동일.
2. **wedge 메시지 1프레임 전달**: "Claude said LGTM. NEKOWORK blocked." 가 narrative 형태로 첨 frame 에 박힘 — Korean OSS 메인테이너의 첨 1초 인지 (P1·P2 동시 충족).
3. **점진 확장 경로 명확**: fixture 1개 → 3·5개 (heatmap row 가능) → live data (Q5 north star). 본 doc 의 1.5주 scope 는 fixture 1개 + interactive replay 만, 나머지는 follow-up.
4. **P3 (1.5주 ship 비용) 보호**: CC 페어 ~20h 추정은 fixture 설계 5-8h + timeline scrubber 8-10h + README GIF 2h + Pages 셋업 2h. 첫 사이클 후 재추정 (Reviewer Concern).

A 는 핵심 narrative 없이는 wedge 못 전달, C 는 6주 시계 + 5-user wedge test 와 충돌.
